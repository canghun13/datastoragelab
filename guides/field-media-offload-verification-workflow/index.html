Capture-to-copy guide

Field Media Offload and Verification Workflow

Define the evidence that moves a card from exposed, to copied, to verified, to safe for reuse.

Plan source media before call time

Start with the expected payload per camera, not only a card's advertised capacity. A photo estimate needs image count and a measured average file size from the intended format. Video needs record minutes and a documented or measured bitrate. Dual-slot recording creates two source copies but also consumes two card paths. Reserve protects against variable-length files and an unexpectedly busy day; spare cards protect against a device that should leave service.

Give every card a visible state

A simple state model prevents memory from becoming the control system. A card begins empty and ready, becomes exposed after capture, becomes copying only while a controlled job is running, and becomes verified only after the selected integrity check succeeds for every required destination. A separate released state records that the hold rule has ended. Labels, cases, or a written log should make the current state obvious without mounting the card.

Separate destinations by failure path

Two folders on one portable SSD are not two independent copies. Two partitions on the same device are also one physical failure path. Assign Copy A and Copy B to different drives. When practical, put them in different bags and different custody after verification. A laptop's internal disk can be useful working space, but count it only when it has enough free capacity and is intentionally included in the copy plan.

Benchmark the complete path

Reader labels, USB generations, and SSD marketing rates do not predict sustained offload time by themselves. Test a full representative card through the travel hub, cable, port, software, and both destinations. Parallel readers raise aggregate source demand, while one slow destination can limit every stream. Include verification in the measured window. If the job must finish overnight, compare total elapsed time with the hours actually available rather than a theoretical 24-hour day.

Choose verification deliberately

A file count and folder size can reveal obvious omissions but do not prove byte identity. A source-to-destination checksum provides stronger evidence. Some applications hash during transfer; others re-read the completed destination and compare it with the source or a saved manifest. A full re-read consumes additional time and drive bandwidth. Record the software, method, completion status, exceptions, and manifest location so another person can audit the handoff.

Do not erase at copy completion

Copying is not the same state as verification, and verification may not be the same state as release. A production can require two verified destinations, a second operator check, physical separation, delivery to post-production, or an extra hold period before a card is formatted. Write that event into the plan. The rotation calculator translates the release delay and processing backlog into a minimum card pool.

Close the field handoff

At the end of each offload, reconcile source cards, file counts, data totals, destination identifiers, verification reports, and exceptions. Eject only after the application and operating system finish writes. Separate the copies, then record who took custody. Use the Field Media Offload tools to size the kit and the copy and verification checklist to close each job. Once media reaches the studio, plan working, archive, and independent backup tiers separately.
