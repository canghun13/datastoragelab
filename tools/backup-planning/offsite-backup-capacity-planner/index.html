Before you start

Enter protected TB, changed percentage, retention periods, and the number of offsite destinations that each need complete recoverability. Do not count replicas inside one provider account as automatically independent. For Offsite Backup Capacity Planner, write the offsite allocation assumption beside every saved result. That remote-capacity requirement record lets another person reproduce the retention and destination count scenario, challenge remote changed-data growth, and rerun Offsite Backup Capacity Planner after conditions change. Test one conservative offsite allocation case and one demanding case, then compare their remote-capacity requirement range.

How the calculation or recommendation works

One remote target equals protected data plus the 0.55-adjusted changed-data reserve. The offsite planner multiplies that reserve-bearing target by the declared destination count to expose total remote allocation. The Offsite Backup Capacity Planner keeps offsite allocation arithmetic transparent, allowing the remote-capacity requirement to be checked without a vendor account. In Offsite Backup Capacity Planner, follow every retention and destination count unit shown by Offsite Backup Capacity Planner. Decimal TB and TiB answer capacity questions. Keep every Offsite Backup Capacity Planner input in its displayed unit; preserve those Offsite Backup Capacity Planner labels when sharing or checking the result. Round the remote-capacity requirement upward only after reviewing the unrounded Offsite Backup Capacity Planner result.

How to interpret the results

Per-copy capacity should be compared with provider quotas or physical-media size; total target reflects every remote copy. Separate this storage question from upload time, egress cost, credential recovery, and restore logistics. Read the Offsite Backup Capacity Planner summary with its offsite allocation metrics. Use the Offsite Backup Capacity Planner table and caution note to examine the complete retention and destination count tradeoff. Save remote changed-data growth inputs with the result, compare scenarios under the same offsite allocation definition, and investigate conflicting remote-capacity requirement output before acting.

Worked example

Four TB changing 5% monthly across twelve periods needs about 5.32 TB for one offsite target. Two independently recoverable remote targets would raise modeled aggregate allocation to about 10.64 TB. This Offsite Backup Capacity Planner example demonstrates the offsite allocation path, not a universal default. Assumptions and limitations

The estimate excludes provider metadata, object versioning rules, minimum billable size, compression, deduplication, deleted-item policy, taxes, egress, throttling, and media shipping. Independence depends on credentials and failure domains. The Offsite Backup Capacity Planner is a planning aid for retention and destination count in Offsite Backup Capacity Planner. Treat the offsite allocation assumptions as boundaries: the remote-capacity requirement supports offsite allocation planning only. It does not certify an implementation of Offsite Backup Capacity Planner, guarantee recovery, or provide financial advice. Recheck remote changed-data growth, documentation relevant to Offsite Backup Capacity Planner, and operating requirements before purchasing for Offsite Backup Capacity Planner, migrating data, or approving a policy.
